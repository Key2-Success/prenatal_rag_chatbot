# Hybrid search: BM25Encoder for sparse vector generation (paired with dense
# OpenAI embeddings). Fitted on the full corpus at ingest time; loaded as a
# singleton at query time. Pinecone's classic index API requires client-side
# alpha scaling (no server-side alpha param) — see retriever.py.
# Pin to 0.11.x — pre-1.0 library; minor bumps can rename API surfaces.
pinecone-text>=0.11,<0.12

# Cross-encoder reranking: bge-reranker-v2-m3 self-hosted via
# sentence-transformers (instead of Pinecone Inference's hosted version).
# Same model — but self-hosted means no per-call API rate limit (Pinecone
# Inference free tier caps at 500 reranks/month, which is 10 evals at our
# scale). First call downloads ~600MB to ~/.cache/huggingface; subsequent
# calls run on CPU at ~50-200ms per (query, 15-candidates) pool.
# Pin: 3.x is the current stable; 4.x will break the import path again.
sentence-transformers>=3.0,<4.0

# PDF parsing: LlamaParse via llama-cloud-services. SOTA for structured-PDF
# extraction: tables as markdown (| col | col |), multi-column layouts
# linearised, OCR fallback for scanned pages. Used only at ingestion time
# (`python -m scripts.ingest`), not at runtime. Previously reverted to pypdf
# (May 2026) after a RAGAS drop — root cause was later traced to a concurrent
# prompt change (bureaucratic few-shot examples), NOT LlamaParse. Re-migrated
# once the prompt was corrected. Pinned to 0.6.x — pre-1.0 library, minor
# bumps can rename API surfaces; re-pin after any upgrade.
# NOTE: llama-cloud-services 0.6.x requires llama-cloud==0.1.46 exactly.
# llama-cloud is pinned below to prevent accidental upgrades (2.x breaks the
# import). Both packages are deprecated; migration to the new unified SDK
# (llama-cloud>=1.0) is deferred until the LlamaParse API stabilises there.
llama-cloud-services>=0.6,<0.7
llama-cloud==0.1.46
